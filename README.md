# NIKKE 客户端拆包方案

> 从 Android 客户端到分类落盘的完整方法论 —— 面向「要定期从游戏里提取美术/文本资源」的场景。

本仓库记录一套经过多次实战验证的拆包流程：怎么把一个模糊需求（「这期新增了什么」）翻译成可执行的提取清单，怎么只取清单内的资源而不做全量扫描，产物按什么格式落盘，以及怎么验收。

所有数字均为实测，不是引用社区文档。

---

## 一句话流程

```
版本三要素 → 基线快照 → ID 集合差 → 定向取件 → 导出校验 → 分类落盘 → 说明 + 联系表
```

---

## 三种工作模式

同一个「拆包」在不同时间点落地成三种形态。**先判模式，再决定目录结构和交付深度。**

| 模式 | 触发场景 | 交付深度 | 目录切法 |
| :--- | :--- | :--- | :--- |
| **A 全量期次** | 新版本首次系统整理，要对外发布图文报告 | 最全（含 PDF / 素材清单 / 构建目录） | 读者导向两段式 |
| **B 版更增量** | 停服更新后，只要「本期新增」并入库 | 深（九段式 + 入库登记 + 联系表） | 采集管线九段式 |
| **C 当日快拆** | 时间紧，当天就要出图 | 浅（平铺分类 + 结果文档） | 类别平铺 |

三者的差异只影响**目录形态与交付深度**，不影响下面五条共性：

1. 先定版本三要素（`versionName` / `versionCode` / `lastUpdateTime`），再动手
2. 先有基线（上一版全量键快照），才谈「新增」
3. 增量判定用 **ID 集合差**，不用键集合差
4. 每件产物必须能倒推回资源键
5. 存疑就标注，不臆造译名、不猜归属

## 快速开始

```bash
# 0. 环境自检（设备在线 / 下载收尾 / 工具链 / 基线）
nikke-extract doctor

# 1. 上一版快照（本版之前先做，只做一次）
nikke-extract snapshot --out baseline/152.8.7

# 2. 停服更新后，与本版做差
nikke-extract diff --base baseline/152.8.7 --out diff/153.6.10

# 3. 按差出来的 ID 清单定向取件
nikke-extract pull --keys diff/153.6.10/new_ids.txt --bucket dp

# 4. 导出
nikke-extract export --in build/dp --out export/

# 5. 按九段式归档 + 生成说明与联系表
nikke-extract archive --mode B --issue 20261029
nikke-extract report  --issue 20261029
```

> 上面是一键工具的**目标形态**。当前这些步骤由一组独立脚本手工串起来，接口约定见 [docs/05_路线图.md](docs/05_路线图.md)。

## 三条最容易被踩错的地方

### ① 键变了 ≠ 新增

直接 diff 两版 catalog 的键清单，会得到「新增 2,747 条 / 删除 1,800 条」这种数字。里面**绝大部分是同一个资源、hash 变了的重打包条目**。

正确做法是从键里正则提业务 ID 做集合差：

```
icons-char-full(hd)_assets_<cID>_<皮肤>_<hash32>.bundle  →  取 cID_皮肤
旧 537 个 ID  →  新 549 个  →  差集 12 个
```

### ② 预埋 ≠ 新增

新版本里出现、但**上一版本地化表里早就存在**的条目，是长期预埋、新表首次登记，不算新增。
基线必须**同服同源** —— 拿国服文本库当国际服基线，会凭空多报一批。

### ③ 导出成功 ≠ 产物正确

UnityPy 对一批包会导出**不动的模型**、**内容错位的 bundle**、**缺件的动画**，三种情况都**不报错**。

必须打自检：

```
objects / triangles / vertices / ratio      ratio ≥ 1.5
animations > 0 且通道数 > 0
file_offset == 已写入长度
不可归组数 == 0
```

## 环境要求

| 项 | 说明 |
| :--- | :--- |
| Android 设备 | 已 root（`su` 可用）。外部存储的 `Android/data` 在国产 ROM 上对 `adb shell` 也封锁，需 `su` 中转 |
| adb | platform-tools，建议 1.0.41+ |
| Python | 3.11+，需 `UnityPy` / `pillow` / `zstandard` |
| 磁盘 | 单版本全量原始约 44.5 GiB（七桶合计），按需取件可压到几百 MB |

> 只想拿静态表（30 MB 级）的话，多数情况下不需要 root —— 前提是 ROM 没封 `Android/data`。全量 28 GB 素材，root 基本是最省事的一条路。
