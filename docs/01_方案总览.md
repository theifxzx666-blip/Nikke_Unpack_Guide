# 01 · 方案总览

> 六阶段执行流程 + 版本证据链 + 增量判定口径。
> 这一篇是「动手前必须读完」的部分，其余文档都是它的展开。

---

## 一、三种工作模式的完整定义

### A · 全量期次

**什么时候用**：新版本首次系统整理；要对外发布图文报告；需要 PDF。

**目录切法 —— 按读者的两个问题，不按采集管线**

```
<YYYYMMDD>_<服>\
├── 00_本期概览.md
├── <日期>_更新内容一览.pdf / _简版.pdf
├── _素材清单.csv                  ← 逐文件：name/kind/mode/size/inode/nlink/src
├── 01_新角色&皮肤\               ← 「这期出了谁」
│   ├── 00_总览\   角色\   皮肤\   卡池与活动横幅\   _其他装扮\
├── 02_主线&活动\                 ← 「这期讲了什么」
│   ├── 00_往期活动索引\  主线_第A-B章\  活动_<名>（<代号>）\
└── _构建\                        ← 中间件，不进清单，可删可重建
```

**为什么不能按采集管线切**：曾经按 `01_新角色 / 02_新皮肤 / 03_活动 / 04_卡池横幅 / 05_主线 / 06_大厅动画 / 07_爆裂特写` 切过一遍，
结果**同一名角色的素材散在 4 个目录里，找一次要点 4 次**。改成两段式后，一名角色一个目录：

```
角色\QUEEN（真）_c870\
├── 角色信息.md
├── 立绘\     立绘 / 立绘_高清 / 半身像 / 小人立绘
├── 技能\     爆裂技能 / 技能1 / 技能2 图标
├── 动画\     大厅_idle · 大厅_action · 爆裂_skillcut（各 GIF + 首帧 PNG）
├── 台词与配音\  台词_全语言.tsv + 语音_日配\
└── _源料\    爆裂贴图 / 时序 / 图集 / 旧版备份
```

**`_源料\` 是技术过程产物的唯一出口**。下划线开头 = 不面向读者、可整块删掉重跑。

| 判据 | 放哪 | 进 PDF |
| :--- | :--- | :-: |
| 游戏里能直接看到 | 上层正式目录 | 是 |
| 为「看懂」重新渲染 / 拆解 / 标注的 | `_源料\` | **是**（它是解释力的一部分） |
| 采集副产物（图集 / 分层时序 / 被替代的旧版） | `_源料\` | 否 |

### B · 版更增量

**什么时候用**：停服更新后，只要「本期新增」，并入母库。

```
<YYYYMMDD>_<服>_<版本>_<主题>\
├── 00_说明.md              ← 版本三要素 + 判定方法 + 新增清单 + 未覆盖项 + 复现命令
├── 01_新增立绘\<名>_c<ID>_<皮肤>\
│      c<ID>_<皮肤>.png      （Sprite 紧裁，与母库同规格）
│      c<ID>_<皮肤>_tex.png  （画布，如 1024²）
├── 02_半身像\<同名目录>\mi_<cID>_<皮肤>_s.png
├── 03_联系表\             ← 每类一张拼图，一眼看完
├── 04_数据\               ← 清单 csv / 取件键 txt / 全量键 tsv
├── 05_新增头像\半身立绘\ + 个人主页小头像\
├── 06_新增称号\usertitle_*_tex.png
├── 07_新增头像框\<中文名>\icn_*_tex.png
├── 08_同步截图\           ← 入站后的下游效果截图（可选）
└── 09_入库登记\入库说明.md
```

**编号即环节，不是凑数**。`00` 说清楚判据，`03` 给人看，`04` 给机器看，`09` 说明怎么并进母库。

### C · 当日快拆

**什么时候用**：停服后 2 小时内要出图。

```
_拆包_<日期>\
├── 01_剧情文本\  02_剧情插画\  03_新角色立绘\  04_头像框\  05_称号图标\ ...
├── 插图清单.tsv    ← 分类 / 文件名 / 尺寸
└── 拆包结果_<日期>.md
```

**不做**：增量判定（凭需求点名的类别直接全取）、入库、PDF。
**必须做**：版本三要素、目录结构树、合计数量与体积、未取项原因。

## 二、六阶段执行流程

### 阶段 0 · 环境自检（每次会话必做，不得跳过）

| 检查项 | 判据 | 不过怎么办 |
| :--- | :--- | :--- |
| 设备在线 | `adb devices` 出现 `device`（非 `unauthorized` / `offline`） | 插线并确认 USB 调试授权 |
| 设备型号 / 系统 | `ro.product.model` / `ro.build.version.release` | 记录进说明（不同 ROM 路径策略不同） |
| 游戏包存在 | `adb shell pm path <包名>` | 包名错或未安装 |
| 版本三要素 | `dumpsys package <包名> \| grep -E "versionName\|versionCode\|lastUpdateTime"` | 取不到就停 |
| **下载已收尾** | `files/tmp/com.shiftup.patch/chunk/ranges` 与 `raw` 为空；全盘无 `.tmp/.part/.dl` 残留 | **未收尾不拆**，否则取到半包 |
| 七桶 revision 齐 | `.patch_state.json` 里 core/dp/fd/en/ja/ko/saus 全在 | 缺桶说明该语种未下发 |
| 工具链 | `python -c "import UnityPy"` 通过 | 缺则装（用国内镜像） |
| 基线存在 | `baseline/<上一版>/` | 无基线则先做全量键快照 |

「下载已收尾」这条最容易漏。曾在清单刷新后立即取件，结果 `StaticData.pack` 还没生成，
误判成「这版没有静态表」。正确的判据是三个证据同时成立：临时目录空壳、无半成品后缀、`existingGroups` 六组齐备。

### 阶段 1 · 取基线与版本对齐

```
基线 = <上一版> 的七桶 catalog 键全量快照
新版 = 当前设备的七桶 catalog.ndb
```

基线内容：七桶 `*_keys.txt`、业务 ID 清单、键基线 JSON。

**文件大小要登记**。这是「版本真的变了」的第一道证据：

| 文件 | 旧 | 新 |
| :--- | --: | --: |
| 主桶 `catalog.ndb` | 17,377,367 B | 18,204,154 B |
| 补丁桶 `catalog.ndb` | 14,295,329 B | 15,522,149 B |
| `StaticData.pack` | 17,563,168 B | 18,083,936 B |

### 阶段 2 · 增量判定

见第四节。产出：`新增键清单` + `新增 ID 清单` + `消失清单`（要说明为什么消失）。

### 阶段 3 · 定向取件

```
① 键 → catalog 查 file_id → chunk_file_map 得 [chunk_id, file_offset]
② chunk → store.cdb.idx 查 (pos, compressed_size)
③ dd 切块（4096 对齐）→ zstd 解压
④ 按 file_offset 拼装（必须校验连续性）
```

细节与三条硬约束见 [03_容器格式.md](03_容器格式.md)。

### 阶段 4 · 导出与校验

| 资源 | 工具 | 必打自检 |
| :--- | :--- | :--- |
| 贴图 / Sprite | UnityPy | 对象数、导出张数、尺寸、alpha 均值 |
| 模型 | UnityPy → glTF | `objects / triangles / vertices / ratio`，`ratio ≥ 1.5` |
| 动画 | glTF | `animations > 0` 且通道数 > 0 |
| 文本 | 自写解析 | 行数、**不可归组数必须为 0** |
| 音频 | 裸 WAV 改名 | 采样率 44100/48000、16 bit、声道数 |

**看不到自检数字就当失败，不要往下游走。**

### 阶段 5 · 分类落盘

按 [02_提取清单.md](02_提取清单.md) 的目录与 [04_落盘与命名.md](04_落盘与命名.md) 的命名规则。

### 阶段 6 · 总结 + 入库 + 索引

- 出说明文档（含 8 项，见第四节末）
- 出联系表
- 入库（仅 A / B 模式）：先查重 → 按母库命名改名 → 写 `入库登记_<日期>.csv`（含 MD5）→ 更新索引
- 索引三件套：资源总清单（md）、资源库清单（xlsx）、角色代号对照表（xlsx）

> 重建资源库清单 xlsx 会**丢弃手工维护的页**。重建后必须补回，否则几轮下来手工页就没了。

## 三、版本证据链

说明文档开头必须有这张表，缺一项不算验收通过：

| 项 | 取法 | 例 |
| :--- | :--- | :--- |
| `versionName` | `dumpsys package` | 153.6.10（旧 152.8.7） |
| `versionCode` | 同上 | 1530610 |
| `lastUpdateTime` | 同上 | 2026-10-29 00:57:14 |
| 七桶 `catalog.ndb` 大小 + mtime | `stat` | 18,204,154 B / 00:57:42 |
| `StaticData.pack` 大小 | `stat` | 18,083,936 B（+520,768） |
| 各桶键数 | SQLite `count(*)` | 26,758 → 27,905 |

| 文件 | 头 4 字节 | 判定 |

| `StaticData.pack` | `3c4c82df` | 无魔数（正常，本身是 AES 密文） |

## 四、增量判定（本方案最易错的一步）

### 4.1 用 ID 集合差，不用键集合差

直接 diff 键清单会得到「新增 2,747 条 / 删除 1,800 条」，里面混着大量
「同一资源、hash 变了」的**重打包条目**。

正确做法：从键里正则提业务 ID，做集合差。

```
icons-char-full(hd)_assets_<cID>_<皮肤>_<hash32>.bundle  →  取 cID_皮肤

旧 catalog 537 个 ID
新 catalog 549 个 ID
差集 = 12 个
```

**同时看「新增」与「消失」**：

| 情形 | 判断 |
| :--- | :--- |
| 有新增、无消失 | 纯追加，可信度高 |
| 新增与消失都很大 | 命名规则变了，**重新核对正则** |
| 有消失 | 要能解释（资源下架 / 改 ID / 换族名） |

### 4.2 正则必须允许连字符

`^icons?-[a-z_()]+` 这种写法会把 `icons-char-si(hd)` 并进 `icons-char`，
导致误判「没有 si 族」，整批小头像被漏掉。

族名正则要明确允许 `-`，例如 `^[a-z-]+\(`。

### 4.3 预埋 ≠ 新增（三种真实反例）

| 反例 | 现象 | 正确判据 |
| :--- | :--- | :--- |
| **跨服基线混用** | 用国服文本库（某表 374 键）当国际服基线，虚报 8 个新增 | 基线必须**同服同源** |
| **长期预埋首登记** | 新表里出现 5 个「完成第 1~5 章后获得」的旧奖励名 | 旧版本文库里这 5 个**本来就有**，属预埋 → 排除 |
| **hash 变化** | 新 catalog 里有 3 个立绘 ID 看着像新增 | 旧 catalog **也有**，只是 hash 变了 → 不算新增 |

### 4.4 双路印证是硬要求

**键集合差 + 表集合差互相校验，两路一致才敢写「新增 N 个」。**

例：称号新增的判定

| 基准 | 旧 | 新 | 差 |
| :--- | --: | --: | :--- |
| 静态表 `UserTitleTable` 行数 | 250 | — | — |
| 新版本地化表 `USERTITLE_NAME_*` 键 | — | 256 | — |
| 键集合差 | | | **+6 / −0** |

`250 + 6 = 256` **严格闭合**，且 250 个旧键全部存在于 256 个新键中（无一删除）——
这是判定成立的硬证据，不是「看起来像」。

### 4.5 未上线预埋的处理

判不出来源的 ID（角色表 / 皮肤表 / 静态表三处都查不到）→
命名 `_未定名_c<ID>_<皮肤>`，**不臆造译名**，说明里单列一节讲判定依据：

> 相邻 ID 全部有官方名（c234 / c240 / c473 / c480 都有），唯独这几个空缺；
> 角色表按 `ResourceId` 查也不在表内 → 判定为客户端预埋、本地化未下发。

这类资源恰恰是拆包的前瞻价值所在，**不算失败**。

### 4.6 说明文档必含 8 项

1. 版本三要素 + 魔数校验
2. 判定方法（为什么不是直接 diff 键）
3. 新增清单表（含尺寸、官方名有无）
4. 未定名 / 未覆盖项，逐条给原因
5. 目录结构树
6. 规格对齐证据（挑 1 个与母库同名资源比尺寸，证明可直接并库）
7. 复现命令
8. 顺带量出的库缺口（可选，但很有用）

### 4.7 诚实三原则

| 原则 | 例 |
| :--- | :--- |
| 拿不到就写拿不到，给原因 | 「12 个低清版未取：设备索引里查不到这批 chunk，尚未下载到本地，需游戏内触发按需下载」 |
| 差异不解释 | 「国际服画布 1024² vs 国服 2048²，差异原因未查明，不做推测」 |
| 不臆造 | 未定名角色不给译名；无专属图的条目标「走通用底图」 |

**说明里不出现「应该 / 可能」**。要么给实测数据，要么写「未查明」。
