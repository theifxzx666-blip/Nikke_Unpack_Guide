# 05 · 路线图：一键拆包工具

> 把六个阶段固化成 7 个子命令。当前这些步骤由一组独立脚本手工串起来，这一篇定义目标接口，
> 让后续实现有明确契约可依。

---

## 一、总体形态

```bash
nikke-extract <子命令> [参数]
```

单入口 + 子命令，不做 GUI。理由：拆包是「跑一次、看产物、改参数、再跑」的循环，
命令行比 GUI 快；而且脚本本身要能被别的脚本调。

---

## 二、七个子命令

| # | 子命令 | 输入 | 输出 | 通过判据 |
| :-: | :--- | :--- | :--- | :--- |
| 1 | `doctor` | — | 环境自检报告 | 8 项全绿 |
| 2 | `snapshot` | 设备 + 桶列表 | `baseline/<版本>/*_keys.txt` | 七桶键数齐全，与 `count(*)` 一致 |
| 3 | `diff` | 基线 + 新版 | `新增键` / `新增ID` / `消失` | 双路印证一致 |
| 4 | `pull` | 键清单 | `build/<桶>/*.bundle` | `file_offset` 拼装校验 0 失败 |
| 5 | `export` | bundle 目录 | `png` / `glb` / `tsv` | 自检四数齐 + `ratio ≥ 1.5` |
| 6 | `archive` | 导出目录 + 模式 | 三模式目录 | 命名 / 规格对齐检查 0 违反 |
| 7 | `report` | 归档目录 | `00_说明.md` + 联系表 + `入库登记.csv` | 8 项必含齐全 |

### 1 · `doctor`

```bash
nikke-extract doctor
nikke-extract doctor --json          # 给下游程序读
```

检查 8 项，每项给出「通过 / 不通过 / 建议动作」：

| # | 检查 | 不通过时的提示 |
| :-: | :--- | :--- |
| 1 | `adb devices` 有 `device` | 「设备未授权，请在手机上确认 USB 调试」 |
| 2 | 目标包已安装 | 「包名未找到，用 `--pkg` 指定」 |
| 3 | 版本三要素可取 | 「dumpsys 读不到，检查权限」 |
| 4 | **下载已完成** | 「临时目录还有 ranges/raw，等下载完再拆」 |
| 5 | 七桶 revision 齐 | 「缺 X 桶，该语种未下发」 |
| 6 | Python 依赖 | 「缺 UnityPy / zstandard，用镜像装」 |
| 7 | 磁盘余量 | 「预计需 X GB，剩 Y GB」 |
| 8 | 基线存在 | 「无基线，新增判定会退化为全量」 |

第 4 项最关键。查三处：`files/tmp/com.shiftup.patch/chunk/ranges` 为空、
`raw` 为空、全盘无 `.tmp/.part/.dl` 残留。

### 2 · `snapshot`

```bash
nikke-extract snapshot --out baseline/153.6.10
```

- 拉七桶 `catalog.ndb` + `store.cdb.idx` + `saus/raw`
- 解 NKDB → SQLite → 导出键清单
- 记录每个文件的**大小 + mtime + 键数**

输出：

```
baseline/153.6.10/
├── _meta.json          ← 版本三要素 + 七桶文件大小/mtime/键数
├── core_keys.txt       ← 逐行一个完整键
├── dp_keys.txt
├── ... (七桶)
└── core.sqlite         ← 解密后的清单，可反复查
```

**幂等**：重跑同一版本不产生新文件，`_meta.json` 完全一致。

### 3 · `diff`

```bash
nikke-extract diff --base baseline/152.8.7 --out diff/153.6.10
```

```
阶段 1  键集合差           key_old ^ key_new
阶段 2  ID 提取            按族正则从键里提业务 ID
阶段 3  ID 集合差          每个族单独算
阶段 4  双路印证           与静态表差集交叉（可选，需静态表）
```

输出：

```
diff/153.6.10/
├── new_keys.tsv        ← 新增键（族, ID, 完整键）
├── gone_keys.tsv       ← 消失键
├── new_ids.tsv         ← 新增 ID（族, ID, 皮肤, 键数）
├── report.md           ← 人读的结论 + 两路印证结果
└── _warnings.txt       ← 正则未命中 / 族名变化 / 消失量异常
```

**`_warnings.txt` 非空就要求人看一眼**，不要直接往下跑。
典型警告：

| 警告 | 含义 |
| :--- | :--- |
| `族 icons-char-si 新增 0 但预期 >0` | 族名正则可能写窄了 |
| `族 X 消失占比 > 30%` | 命名规则可能变了 |
| `键差 2,747 但 ID 差 12` | 正常（hash 重打包），但要在报告里解释 |

### 4 · `pull`

```bash
nikke-extract pull --keys diff/153.6.10/new_keys.tsv --bucket dp --out build/dp
nikke-extract pull --keys k.txt --bucket core --jobs 4 --dry
```

- 按 `pos` 排序，间隔 > 32 MiB 断批
- 每批一次 `dd` + 一次 `adb pull`
- 解 zstd，断言 `len == original_size`
- 按 `file_offset` 拼装，断言连续性
- **失败不静默**：任何断言失败即中止并打印是哪一块

输出 `build/dp/_pull_log.tsv`：键 / 块数 / 字节 / 耗时 / 状态。
**重跑跳过已成功项**（按键 + 输出文件存在 + 字节数匹配判定）。

### 5 · `export`

```bash
nikke-extract export --in build/dp --out export/ --type image
nikke-extract export --in build/core --out export/ --type model
nikke-extract export --in build/core --out export/ --type spine
```

按类型分派：

| type | 产物 | 自检 |
| :--- | :--- | :--- |
| `image` | `.png` | 导出张数 = 包内 Sprite/Texture2D 数；抽样 alpha 均值 ≠ 0 |
| `model` | `.glb` | `objects / triangles / vertices / ratio`，`ratio ≥ 1.5` |
| `spine` | `.skel/.atlas/.png` | 文件三件套齐；`skel` 头版本可识别 |
| `text` | `.tsv` | 行数；**不可归组数 = 0** |
| `audio` | `.wav/.mp3` | 采样率 / 位深 / 声道 |

**每个产物必须打印自检四数，缺一不可。** 看不到就当失败。

### 6 · `archive`

```bash
nikke-extract archive --in export/ --mode B --issue 20261029 --title 四周年
nikke-extract archive --in export/ --mode A --issue 20260813
```

- 按 [04_落盘与命名.md](04_落盘与命名.md) 建目录
- 应用命名规则（去零 / 补零 / `_tex` / 未定名）
- 查中文名对照表；查不到 → 标 `_未定名_`，**不阻断**
- 落盘后跑一遍检查：

| 检查 | 判据 |
| :--- | :--- |
| 命名合规 | 目录名匹配 `_c<digits>_<digits>$` 或 `_未定名_c...` |
| 规格合规 | 尺寸落在该类的实测区间内 |
| 无重复 | 文件 MD5 不重复 |
| 无 `.bak` | 交付目录干净 |
| 源→目标映射完整 | 每个产物都能倒推回键 |

### 7 · `report`

```bash
nikke-extract report --issue 20261029 --contact-sheet
```

产出：

| 产物 | 内容 |
| :--- | :--- |
| `00_说明.md` | 8 项必含（见 [01_方案总览.md](01_方案总览.md) 4.6） |
| `03_联系表\*.png` | 每类一张 + 装配预览 |
| `04_数据\入库登记.csv` | 逐文件 MD5 |
| `09_入库登记\入库说明.md` | 落库位置 + 命名归一 + 口径差异 |

`00_说明.md` 用模板生成，**但「未覆盖项」和「口径差异」两节必须人工填** ——
脚本不知道你为什么没取某一批。

## 三、接口约定

### 环境变量

| 变量 | 作用 | 默认 |
| :--- | :--- | :--- |
| `NIKKE_ADB` | adb 可执行文件 | PATH 里的 `adb` |
| `NIKKE_PY` | 带 UnityPy 的 Python | 当前解释器 |
| `NIKKE_WORK` | 工作区根 | 当前目录 |
| `NIKKE_PKG` | 游戏包名 | — |
| `NIKKE_BASELINE` | 基线根 | `./baseline` |

### 通用参数

| 参数 | 作用 |
| :--- | :--- |
| `--dry` | **默认开**，只打印要做什么 |
| `--go` | 真正写盘 |
| `--json` | 输出机读 JSON |
| `--jobs N` | 并发数 |
| `--force` | 覆盖已有产物（默认跳过） |

### 编码

子进程强制 UTF-8：

```
PYTHONIOENCODING=utf-8
PYTHONUTF8=1
```

否则中文控制台下 UnityPy / json 里的中文会直接炸。Windows 上这是必然踩的坑。

### 路径

- 支持相对 / 绝对
- 中文路径：Python 用 `os.fsencode`，PowerShell 用 `-LiteralPath`
- 路径里含 `[` `]` `(` 时，通配符匹配会误判 —— 一律当字面量处理

### 返回码

| 码 | 含义 |
| :-: | :--- |
| 0 | 全部成功 |
| 1 | 有告警但产物可用（如部分未取） |
| 2 | 判据不通过（产物存在但不合格） |
| 3 | 环境 / 输入错误，未开始 |
| 4 | 中途失败，产物不完整 |

**「脚本返回 0 但产物不合格」必须算失败。** 判据只信产物，不信「跑过了」。

## 四、实施顺序

按依赖倒序做，每一步都能独立验收：

| 步 | 子命令 | 为什么这个顺序 | 验收方式 |
| :-: | :--- | :--- | :--- |
| 1 | `doctor` | 所有后续步骤的前提，且最容易写 | 换三台设备跑，结论一致 |
| 2 | `snapshot` | 幂等，可反复跑不出副作用 | 同版本连跑两次，`_meta.json` 字节一致 |
| 3 | `diff` | 纯离线计算，不依赖设备 | 拿两个已保存的基线回放，结果与手工核对一致 |
| 4 | `pull` | 唯一碰设备写盘的部分 | 取 50 个键，逐块断言全通过 |
| 5 | `export` | 依赖 `pull` 的产物 | 与历史手工导出的图逐像素比对 |
| 6 | `archive` | 依赖 `export` | 拿历史期次回放，目录树能对上 |
| 7 | `report` | 最后做，因为模板要人定 | 生成的说明能直接交付（只改两节） |

**回放测试**：第 3、6、7 步都能用「已存盘的历史数据」验证，不需要连设备。
这三步应该先做成可回放的，后面调模板才有反馈。

---

## 五、明确不做的部分

| 不做 | 原因 |
| :--- | :--- |
| 全自动判定「这个 ID 是什么角色」 | 中文名只有对照表一个来源，自动推断会臆造译名 |
| 全自动生成 PDF | 版式依赖当期内容（几页角色、几张插画），写死了必出错 |
| 自动删除 / 覆盖母库 | 只新增不覆盖是红线，工具不提供删除能力 |
| 绕过权限获取 | 需要 root 的场合如实报错，不做提权 |

## 六、当前状态

| 能力 | 状态 |
| :--- | :--- |
| NKDB 解密 | ✅ 已有可用实现 |
| CIDX 解析 + dd 取件 | ✅ 已有可用实现，含断批优化 |
| 键 diff / ID 集合差 | ✅ 已有可用实现（各期次脚本） |
| 图片 / 模型 / Spine / 文本导出 | ✅ 已有可用实现（UnityPy） |
| 三模式归档 | ⚠ 半自动，命名与检查靠人眼 |
| 联系表 | ⚠ 每期手写脚本 |
| 说明文档生成 | ❌ 手写 |
| 统一入口 | ❌ 无 |

也就是说：**底层能力都有，缺的是统一入口和上层编排。**
路线图的价值在于先定契约，避免各期脚本继续各写一套。
