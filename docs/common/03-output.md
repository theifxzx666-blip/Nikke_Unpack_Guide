# 落盘与命名

产物能不能被人用起来，九成取决于这一篇。

## 命名四条

| 规则 | 内容 | 依据 |
| :--- | :--- | :--- |
| 目录名 | `<中文名>_c<ID去前导零>_<皮肤>` | 母库既有写法：`尼恩：蓝色海洋_c14_00`、`白雪公主_c220_00` |
| 文件名 | 保留补零，如 `c040_00.png` | 母库既有写法：`角色立绘\D_c040_00\c040_00.png` |
| 无官方名 | `_未定名_c<ID>_<皮肤>`，入库时改 `<cID>_c<ID>_<皮肤>` | 母库未收录写法：`c942_c942_00` |
| `_tex` 后缀 | 母库规格用 `_tex.png`，下游不要 `_tex` | 下游是 Texture2D 原名加 `.png` |

目录去零、文件名留零，这是母库的历史写法，不是设计出来的，不要「统一」它。统一了就要重命名几千个既有文件，还会破坏已经引用这些路径的下游。

判据来源：`角色立绘\D_c040_00\c040_00.png` 里目录是 `c040`、文件名是 `c040_00`，同时 `尼恩：蓝色海洋_c14_00` 的目录是 `c14`，两种写法并存。

改名映射必须写进说明。采集时的名字和入库后的名字可能不同，例如 `c018_01` 变成 `c18_01`。映射表不落文档，下期没人能把交付件倒推回资源键。

| 采集目录 | 入库目录 |
| :--- | :--- |
| `尼恩：透视之眼_c018_01` | `尼恩：透视之眼_c18_01` |
| `_未定名_c235_00` | `c235_c235_00` |

中文名来源唯一：`索引\角色代号中文名对照表.xlsx`。缺失就问人，不得自行命名。曾经因为自行译名，同一角色在三个目录里出现三个名字，后来花半天对齐。

## 模式 A 全量期次

```
<YYYYMMDD>_<服>\
├── 00_本期概览.md
├── <日期>_更新内容一览.pdf / _简版.pdf
├── _素材清单.csv                  逐文件：name/kind/mode/size/inode/nlink/src
├── 01_新角色&皮肤\                「这期出了谁」
│   ├── 00_总览\
│   ├── 角色\<名>_c<ID>\
│   ├── 皮肤\<名>_c<ID>_<皮肤>\
│   ├── 卡池与活动横幅\
│   └── _其他装扮\
├── 02_主线&活动\                  「这期讲了什么」
│   ├── 00_往期活动索引\
│   ├── 主线_第A-B章\
│   │   ├── 00_总览\
│   │   ├── 01_章节与关卡\
│   │   ├── 02_剧情\       剧情插画 / 章节预告图
│   │   ├── 03_地图\
│   │   ├── 04_战斗场景\
│   │   ├── 05_莱彻与BOSS\  立绘 / 关底BOSS / 动图 / 技能图标 / 数据 / _源料
│   │   └── 06_BGM\
│   └── 活动_<名>（<代号>）\
│       ├── 01_插画\  02_剧情\  03_玩法与奖励\  04_图标与文本\
└── _构建\                        中间件，不进清单，可删可重建
```

角色目录的完整形态：

```
角色\QUEEN（真）_c870\
├── 角色信息.md
├── 立绘\     立绘 / 立绘_高清 / 半身像 / 小人立绘
├── 技能\     爆裂技能 / 技能1 / 技能2 图标
├── 动画\     大厅_idle.gif · 大厅_action.gif · 爆裂_skillcut.gif，各加首帧 PNG
├── 台词与配音\  台词_全语言.tsv 加 语音_日配\
└── _源料\    爆裂贴图 / 时序 / 图集 / 旧版备份
```

`_源料\` 是技术过程产物的唯一出口。下划线开头表示不面向读者，可整块删掉重跑。

| 判据 | 放哪 | 进 PDF |
| :--- | :--- | :-: |
| 游戏里能直接看到的 | 上层正式目录 | 是 |
| 为了让人看懂而重新渲染、拆解、标注的 | `_源料\` | 是，它本身是解释力的一部分 |
| 采集副产物，如图集、分层时序、被替代的旧版 | `_源料\` | 否 |

`_源料\` 里的东西在清单里照登，`kind` 标 `源料*`。

三类不进期次：

| 项 | 理由 |
| :--- | :--- |
| 往期活动剧情正文 | 跨期共用，每期复制一遍没有新增信息，只留 `往期活动索引\` |
| BGM 的 wav | mp3 是同源转码，听感无差，体积差 8 倍 |
| 3D 查看器 glb 加网页 | 报告里放线上地址加预览截图即可 |

## 模式 B 版更增量

```
<YYYYMMDD>_<服>_<版本>_<主题>\
├── 00_说明.md
├── 01_新增立绘\<名>_c<ID>_<皮肤>\
│      c<ID>_<皮肤>.png          Sprite 紧裁
│      c<ID>_<皮肤>_tex.png      画布
├── 02_半身像\<同名目录>\mi_<cID>_<皮肤>_s.png
├── 03_联系表\
│      联系表_新增立绘.png / 联系表_新增半身像.png
│      联系表_新增小头像.png / 联系表_新增称号.png
│      联系表_新增头像框.png
│      预览_新头像框装配效果.png / 预览_新小头像.png
├── 04_数据\
│      新增立绘清单.csv / 新增头像清单.csv / 新增称号清单.csv / 新增头像框清单.csv
│      本次取件_HD键清单.txt        逐行一个完整 bundle 键
│      新增键_<桶>_全量.tsv
│      入库登记_<日期>.csv          逐文件加 MD5 加字节
├── 05_新增头像\半身立绘\ 加 个人主页小头像\
├── 06_新增称号\usertitle_*_tex.png
├── 07_新增头像框\<中文名>\icn_*_tex.png
├── 08_同步截图\                  入站后的下游效果截图，可选
└── 09_入库登记\入库说明.md
```

编号对应环节，不是凑数：

| 段 | 给谁看 | 作用 |
| :-: | :--- | :--- |
| `00` | 人 | 判据与结论 |
| `01`~`02`、`05`~`07` | 人 | 产物本体 |
| `03` | 人 | 不打开文件夹就能看完 |
| `04` | 机器 / 下期 | 清单、键、MD5 |
| `08` | 人 | 入库后的实际效果 |
| `09` | 接手的人 | 怎么并进母库 |

入库登记的字段：

| 字段 | 说明 |
| :--- | :--- |
| 资源类型 | 角色立绘 / 半身立绘 / 小头像 / 称号 / 头像框 |
| 入库子目录 | 母库里的相对路径 |
| 逻辑名 | 产物文件名 |
| 状态 | `OK` 或跳过原因 |
| 源文件 / 目标文件 | 绝对路径，便于回滚 |
| MD5 / 字节 | 校验用 |
| 入库前后计数 | 让人知道动了多大量级 |

入库脚本必须只新增不覆盖，默认干跑，加 `--go` 才写盘，写完逐文件校 MD5。

## 模式 C 当日快拆

```
_拆包_<日期>\
├── 01_剧情文本\
├── 02_剧情插画\
├── 03_新角色立绘\
├── 04_头像框\
├── 05_称号图标\
├── 06_地图场景\
├── 07_莱彻\
├── 插图清单.tsv        分类 / 文件名 / 尺寸
└── 拆包结果_<日期>.md
```

不做增量判定、入库、PDF。必须做四件：

1. 版本三要素
2. 目录结构树，带数量
3. 合计数量与体积
4. 未取项加原因。不做增量判定，就必须说清哪些没取。

## 跨服规格对齐

同一份资源在不同服或不同批次可能规格不同，必须核对，不能假设一致。

| 资源 | 国际服实测 | 国服 / 母库 | 处理 |
| :--- | :--- | :--- | :--- |
| 立绘画布 | 1024² | 2048² | 原样入库，索引标注，不推测原因 |
| 称号 | 256×68 称号牌 | 64×64 图标 | 单列子目录，不混放 |
| 半身像高 | 256×450~504 | 多为 256×512 | 原样入库，宽度一致、比例正常 |
| 头像框 | Texture2D 256×256 | 同上 | 一致，可直接并库 |

对齐证据必须写。挑一个与母库同名的资源比尺寸，作为可以直接并库的证据：

> `icons-char-full(hd)_assets_c082_00` 的 Sprite 是 405×761，与母库 `角色立绘\丽塔_c082_00\c082_00.png` 的 405×761 完全一致，说明母库「角色立绘」就是本族 Sprite，本次产物可直接并库。

没有这句，就没人敢并库。

## 联系表

| 项 | 要求 |
| :--- | :--- |
| 用途 | 不打开文件夹就知道这期有什么 |
| 粒度 | 每类一张，如 `联系表_新增立绘.png` |
| 布局 | 网格，每格下标编号或名称 |
| 背景 | 深色底或纯色底，避免透明图在白底上看不见 |
| 必配 | 装配效果预览，头像框套在头像上、头像缩到 128×128 的实际显示尺寸 |

两个反例：

| 反例 | 后果 |
| :--- | :--- |
| 只放原图不放编号 | 无法对回清单，等于没用 |
| 只出一种规格 | 看不出尺寸差异，256×68 称号牌和 64×64 图标放一起看不出区别 |

## 防重复采集

三键查重，硬约束：

| 键 | 查哪 |
| :--- | :--- |
| 资源键 | 资源总清单 / 已采集清单 |
| 文件 hash | 母库全量 hash 索引 |
| 角色代号 | 角色代号对照表 |

同一文件不得在库内出现第二份。一个资源键对应唯一路径，禁止自创目录名，禁止换个文件夹重复采集。

多规格去重的保留优先序：

```
① 未和谐版优先 → ② 像素面积最大 → ③ 文件字节最大
```

跨目录去重不要自作主张。实测某次全量去重删掉 16,783 份，释放 8.90 GB，但其中跨目录的 SD 到 HD 共 312 项是人工裁决跳过的，因为 SD 和 HD 在业务上可能是两种东西，不算重复。

重建索引会丢手工页。资源库清单 xlsx 里有若干人工维护的页，包括本轮变更、非可玩立绘、处置说明，自动重建会把这些页丢掉，重建后必须补回，否则几轮下来手工内容就没了。建库时的备份放 `_基线\*_pre.xlsx`。

## 临时产物

| 类型 | 去处 | 多久清 |
| :--- | :--- | :--- |
| 脚本 | `脚本\` | 长期保留 |
| 中间图集 / 时序 / 旧版 | `_源料\` | 随期次 |
| 版式核对截图 / 调试图 | `回收站\<日期>_<说明>\` | 随期次 |
| `.bak` 文件 | 不进交付目录 | 立即 |

交付目录里不留 `.bak`。要留就放回收站，并在说明里写清是什么。
