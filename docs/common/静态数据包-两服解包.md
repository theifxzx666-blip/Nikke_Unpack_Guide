# 静态数据包：国服 / 国际服两服解包链路

关卡、角色、概率这些配置不在美术容器里，客户端也不落盘全量静态表。它们由服务器按版本下发一个 `StaticData.pack`，要走另一条链路拿。这篇把两服的入口、解包、读表和已知边界收在一处。

**边界**：只对公开接口和已下载的文件做只读读取。不装证书、不抓包解密、不注入、不读内存、不碰登录。静态表是下发的配置数据，游戏运行时状态（比如"今天开哪个池"）不在这条链路里。

与四场景取件的关系：七桶 / 缓存那套解决美术和音频，这篇解决数值配置。两条链路不交叉——客户端里找不到静态表不代表数据不存在，去问 lobby。

## 一、两服入口对照

| 项 | 国服 | 国际服 |
| :--- | :--- | :--- |
| lobby | `lobby.nikkecn.qq.com:12001` | `global-lobby.nikke-kr.com:443` |
| 路径 | `/v1/get-static-data-pack-info` | `/v1/get-static-data-pack-info-mpk` |
| 请求 | 空 protobuf POST | 空 protobuf POST |
| `Content-Type` | `application/octet-stream+protobuf` | 同左 |
| 实测版本 | `data/ob18/152025` | `data/qa-261119-10b-p1/580722` |
| 包体积 | 约 19 MB | 约 18 MB |
| 解出规模 | 8,986 文件（json 8,972 / csv 13 / tsv 1） | 本轮只解 Gacha / CharacterTable 相关 48 个 `.mpk` |
| 路径后缀 | **没有** `-mpk`，加了 404 | **有** `-mpk`，去掉取不到 |

域名不是猜出来的：从游戏实际连接与 TLS 证书定位 `*.nikkecn.qq.com` 一族，国际服从客户端配置里的 `global-lobby.nikke-kr.com`。早期试的 `a2.yongxinghudong.com.cn`、`nikke.qq.com` 都是 404 / 502，别再走。

国服 DNS 解析出的 IP 会变；需要 `--resolve` 时以**当时实测**的 IP 为准，不要抄旧值。

## 二、取包信息与 protobuf 解析

两服都用一个空 body 的 POST，响应是 protobuf：

```bash
# 国服（<实测IP> 换成当时的解析结果）
curl -sk -m 12 --noproxy '*' \
  --resolve "lobby.nikkecn.qq.com:12001:<实测IP>" \
  -X POST \
  -H "Content-Type: application/octet-stream+protobuf" \
  -H "Accept: application/octet-stream+protobuf" \
  --data-binary "" \
  -o static_info.pb \
  "https://lobby.nikkecn.qq.com:12001/v1/get-static-data-pack-info"

# 国际服（无需 --resolve）
curl -s -m 20 --noproxy '*' -X POST \
  -H "Content-Type: application/octet-stream+protobuf" \
  -H "Accept: application/octet-stream+protobuf" \
  --data-binary "" \
  -o static_info.pb \
  "https://global-lobby.nikke-kr.com/v1/get-static-data-pack-info-mpk"
```

请求体是空的，等价于请求消息全部字段取默认值。响应字段固定六个，不装 protoc 也能读：

| 字段号 | 类型 | 含义 |
| ---: | :--- | :--- |
| 1 | string | 包下载地址 |
| 2 | int | 包大小 |
| 3 | bytes | SHA256 |
| 4 | bytes | salt1 |
| 5 | bytes | salt2 |
| 6 | string | 版本号 |

手写 varint 就够：

```python
def varint(b, i):
    v = 0
    s = 0
    while i < len(b):
        c = b[i]
        i += 1
        v |= (c & 0x7f) << s
        if not c & 0x80:
            break
        s += 7
    return v, i
```

wire type 2 读 `length + bytes`，wire type 0 直接读 varint。salt1 / salt2 以 bytes 原样传给解包脚本，不要 base64 之后再传。

## 三、下载、校验、解包

拿到 url 后下载 `.pack`，先用字段 3 的 SHA256 校验，再走双层 AES。国服 `152025` 包实测 SHA256：

```
d422f83f1687ac0e8e4a77b48aca5e77f37925d51c4534fad23c8d973c2f5375
```

双层 AES 的算法、PRESHARED 与 salt 的关系见 [容器-国际服.md](容器-国际服.md)「StaticData.pack 是唯一的双层 AES」。这里只重复最容易翻车的判据：

- `SALT1` / `SALT2` **随版本下发**，从上面的接口取，绝不硬编码；客户端内嵌的 PRESHARED 常量本仓库不提供。
- 解完先判前两字节是不是 `PK`。不是 → salt 与包不匹配（版本串了，或用了别服的 salt），不是算法错。
- 早期把「常量固定」当前提，试过 salt 互换、迭代 1k/10k/100k、GUID 当 password 等全部无效——根因就是 salt 按版本变。

解包产物是真 zip，里面约 9,000 多个 `.mpk`。转 JSON 需要 MemoryPack schema：从 `global-metadata.dat` 还原类与成员顺序，逐表看 `leftover_bytes` / `rows_match` 验收。**新版本可能改字段**——国际服 580722 的 `GachaTypeTable` / `GachaSelectupListTable` 就因为 schema 版本差异解失败或残余，但 `GachaGradeProbTable`（789 行）和 `GachaListProbTable`（17,270 行）正常。工具报错不等于"这个池不存在"，换表交叉验证再下结论。

## 四、读表口径：字段大小写与概率链路

### 4.1 两服字段不是同一套

| | 国服 | 国际服 |
| :--- | :--- | :--- |
| 字段命名 | 小写 `id` / `group_id` / `reward_type` / `ratio` / `name_localkey` | 大写 `Id` / `Group_id` / `Gacha_list_id` / `Prob` / `Name_localkey` |
| 稀有度 | 字符串 | 数字：`3=SSR`、`2=SR`、`1=R` |
| 外层结构 | `{"records": [...]}` | 部分表直接是 list |

跨服脚本直接复用键名会**静默读空**，不报错。取数前先打印一行样本看键名。

角色 ID 两服通用，中文名走国服 `CharacterTable.id` → `Locale_Character.lss` 的 `[zh-CN]`。国际服独有的新角色在国服表里查不到，用母体 A 的 `character_identity.json` 按资源号（`ID // 100 % 1000`）补名；实在没权威译名的写 `角色<ID>` 占位，不要音译编造。

### 4.2 随机箱（征调令）

征调令是**随机箱**，不是抽卡池；铸模是材料道具，也不是征调令。三者别混。

```
ItemConsumeTable.records[].name_localkey = randombox_*
  → use_type = ItemRandomBox
  → use_id = 99800003..99800007
ItemRandomTable.records[].group_id = use_id
  → reward_type / reward_id / ratio
CharacterTable.id → Locale_Character.lss.[zh-CN]
```

概率 `p = 本行 ratio ÷ 组内 ratio 总和`。朝圣者 / 超标准征调令实测：14 个角色各 `ratio=100`，完美铸模 `ratio=1400`，组和 2,800 ⇒ 每角色 **3.5714%**、铸模 **50.0000%**，即 `1/(2N)` 与 50%。

高品质 SSR 那组是例外：`ratio=5,371`，算出来 39.0023%，不是整数倍关系。**照抄原始比值，别"修正"成 50%。**

### 4.3 抽卡池（Gacha）

```
GachaTypeTable.grade_prob_id
  → GachaGradeProbTable(group_id, rare, prob, prob_max_count, gacha_list_id)
  → GachaListProbTable(group_id, gacha_id, prob)

选择招募候选另走 GachaSelectupListTable.character_id
```

- `prob` 是**万分比**；`prob_max_count=0` 或 `10000` 都表示分母固定一万，不是零概率。
- 角色绝对概率 = 档位概率 × 组内权重占比。
- 普通池 SSR `350+50=400/10000=4%`、SR 43%、R 53%，与游戏公示一致。
- 当前在架池多为 1% 型（`100+250+50=400`），旧池有 2% 型（`200+150+50`）。两档别混用。

**静态表只给骨架，不给档期**：115 个池没有 Start / End 字段，当期角色常是 `gacha_id=0` 占位，由服务端运行时填。所以"今天开哪个池"只能靠官方公告判定，不能拿池 ID 反推角色——实测国服 `90001` / `90002` 的当期是画皮 / 婴宁，不是同期公告里的娜由塔 / 莉贝雷利奥；那两个新角色的 ID 在 9,702 行名单里命中 0 次。证据分两层：**档期与当期角色以公告为准，4% 怎么拆以静态表为准。**

国际服名单比国服大：1% 型池常驻 SSR 105 人（国服 84）、朝圣者 21 人（国服 14）。别互相套用。

## 五、踩坑清单

1. **后缀别互换**：国服没有 `-mpk`（加了 404），国际服有。
2. **截图读数**：`3.5714% = 1/28`，不是 `3.514%`。看不清就放大，别按错误读数编出"缺口"。
3. **字段大小写**：国服小写、国际服大写，混用读空不报错。
4. **`prob_max_count=0`**：分母固定一万，不是零概率。曾因此误判"特殊池 4% 不在静态表"。
5. **当期角色占位**：`gacha_id=0` 要服务端填；池 ID 不能反推角色。
6. **解析残余 ≠ 数据缺失**：按 `leftover_bytes` 判断，换表交叉验证后再下结论。
7. **译名真源**：改显示名只改增强字典的 `cnName` 才生效；`character_name_mapping.json` 那类 `chineseName` 改了不影响 Bot。重跑 `apply_cn_client_roster.py` 会覆盖人工订正，要写进脚本的 `MANUAL_NAME_FIXES`。
8. **代理端口**：推送前先探。`HTTP(S)_PROXY` 指向不可用端口会把 git 的 CONNECT 打成 502 / 000；显式覆盖或换当前可用端口。
9. **行尾**：本仓 `.gitattributes` 是 `* -text`，CRLF / LF 混合是常态。编辑工具改 CRLF 文件会静默转 LF，产生整文件假 diff——按原行尾字节改写，改完 `git diff -w --stat` 复核。

## 六、覆盖与缺口

**已覆盖**：两服静态包拉取与解包、征调令概率、卡池权重骨架、概率公示交叉验证。

**未在静态包内**：

- 池的 Start / End 与当期角色填充 —— 服务端运行时下发，靠公告。
- 时装抽取（`EventBoxGacha`）与新手 / 社交点招募 —— 另一套表族，不在这三张 gacha 表里。
- 游戏内"概率情报"页实时截图 —— 本轮用官方公告替代，数值一致但没有逐行截图留证。

**脚本与数据落点**：解包与导表脚本属"解包之后"的离线加工层，不公开在本仓库；本仓库只登记方法、判据和口径。表本体也不入库（见 [AGENTS.md](../../AGENTS.md) 硬底线）。
