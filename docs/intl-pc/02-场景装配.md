# PC 端战斗场景装配与离线渲染（spotbackground）

> 适用：`spotbackground(hd)_assets_sbg_*.bundle`——战斗背景（`sbg_` 前缀），与 `scenariobackground` 的**单张全景**不同，这类是**装配型 2.5D 场景**。
> 结论来源：2026-10-29 四周年 5 个包（`sbg_finale_xbg006_001_01` / `_01_custom` / `_02` / `sbg_skyfallxba003hsta_001` / `sbg_skyfallxba004_001`）全部渲染通过。
> 实现：`拆包\04_临时车间\脚本\tmp_sbg_lib.py` + `tmp_sbg_render.py`。

---

## 一、包里有什么

以 `sbg_finale_xbg006_001_02` 为例（490 对象 / 66 MB 解包后）：

| 类型 | 数量 | 用途 |
|:--|:--:|:--|
| `Texture2D` | 41 | 每张一个场景层 |
| `Sprite` | 36 | 贴图 + `m_Rect`（决定四边形尺寸与 UV） |
| `MeshFilter` / `MeshRenderer` | 46 / 46 | **41 个是 Sprite 四边形（`m_Mesh=0`）+ 5 个真网格（地形）** |
| `Mesh` | 20 | 实际被引用的只有 5 个 |
| `Material` | 5 | `NKMaterial_Background*`，共用，`_MainTex` **指向包外** |
| `MonoBehaviour` | 121 | 装配信息（见下） |
| `Transform` / `GameObject` | 88 / 88 | 单根、深度 ≤ 4 |

关键脚本（`MonoScript.m_ClassName`）：

| 类 | 作用 |
|:--|:--|
| `SpotSingleMap` | **场景根**。8 个 root 指针：`rootCover` / `rootDynamicHardObject` / `rootDynamicMediumObject` / `rootDynamicObject` / `rootDynamicSoftObject` / `rootGround` / `rootNonCollisionObject` / `rootStaticObject`，另有 `Cover1~5`、`spotSky`、`IsOnScroll`、`*Speed` |
| `NKSpotCoverManager` | 机位：`cameraPosition` / `characterPosition` / `coverObject`（每场景 5 个） |
| `RuntimeTextureInstanceSetter` | **贴图绑定的真正入口**：`_sprite` + `_material` |
| `NKSpotSky` | 只挂 `mMaterial`，天穹由运行时生成 |
| `SpotBG` / `SpotGroupMap` / `NKSpotCover` / `NKSpotCoverObject` / `NKSpotNonColObject` / `NKTransformDetector` | 分组、遮挡、触发器 |

## 二、装配还原的五条（按踩坑顺序）

### 1 贴图不在 Material 上

`Material._MainTex` 的 `m_FileID=2`、`m_PathID=8501139332677272989` 在**本包内查不到任何对象**——它指向包外共享资源。
真正的绑定是每个四边形上的 `RuntimeTextureInstanceSetter`：

```
RuntimeTextureInstanceSetter {
    _sprite   : PPtr<Sprite>     ← 贴图与 UV 的唯一来源
    _material : PPtr<Material>   ← 共用 NKMaterial_Background
}
```

**判据**：`Texture2D` 数 == `RuntimeTextureInstanceSetter` 数（本例 41 == 41）。数量对上就说明贴图全在 setter 上。

### 2 `m_Mesh = 0` 不代表没几何

46 个 `MeshFilter` 里只有 5 个挂了 `m_Mesh`，其余 41 个是 0——**Sprite 四边形由运行时按 `Sprite.m_Rect / m_PixelsToUnits` 生成**。
所以还原时自己造四边形：

```
w = m_Rect.width  / m_PixelsToUnits      # ppu 实测全为 100
h = m_Rect.height / m_PixelsToUnits
uv0 = (m_Rect.x / texW, m_Rect.y / texH) # 右下，Unity 原点左下
uv1 = ((m_Rect.x + m_Rect.width) / texW, (m_Rect.y + m_Rect.height) / texH)
```

「这个包没有 Mesh，所以没资产」是**错的**——先数 setter。

### 3 索引缓冲为空时用隐式顺序索引

部分包 `Mesh.m_IndexBuffer` 长度为 0，而 `m_VertexData.m_DataSize` 正常、`m_SubMeshes[].indexCount` 正常。
此时索引就是 `firstVertex + 0..indexCount-1`。照 `firstByte` 去 `unpack_from` 必炸：

```
struct.error: unpack_from requires a buffer of at least 312 bytes ... (actual buffer size is 0)
```

5 个包里 4 个栽在这条。**修法**：

```python
if len(ib) < first + cnt * 2:
    base = int(sm.get("firstVertex") or 0)
    idx = list(range(base, base + cnt))
else:
    idx = list(struct.unpack_from("<%dH" % cnt, ib, first))
```

### 4 一个 bundle 可能装两个场景

`_01_custom`（90 MB）里有 **2 个 `SpotSingleMap`**：`sbg_finale_xbg006_001_01`（105 绘件 / 5 机位）与 `_02`（46 / 5），合计 151 绘件、10 机位。
不分组的直接后果是两套场景叠在一张图上（天际线悬在废墟半空）。

分组方法：用 `SpotSingleMap` 的 8 个 root 各自展开子树，得到成员 Transform 集合；绘件与机位按 `transform ∈ 集合` 归组。

### 5 相机在 `NKSpotCoverManager` 上，且是 GameObject

```
NKSpotCoverManager { cameraPosition: PPtr<GameObject>, characterPosition: PPtr<GameObject>, coverObject: PPtr<MonoBehaviour> }
```

要再经一层 `GameObject → Transform` 才拿到世界位姿。**Unity 相机前向 = 旋转矩阵第 3 列（+Z）**，`-R[:,2]` 是反的，写反会渲染到背后一片空。

## 三、渲染管线（无 GL 依赖）

环境 `venv_assetparse` 只有 `numpy` + `Pillow`，无 `trimesh` / `pyrender` / `moderngl` / `scipy` ⇒ 自写软光栅。

| 环节 | 做法 |
|:--|:--|
| 世界变换 | 递归 `m_Children` 累乘（位置 + 四元数→矩阵 + 缩放），求 `world` |
| 顶点 | 网格走 `m_VertexData`（通道 0 = position，通道 4 = uv0）；四边形走 `m_Rect/ppu` |
| 相机 | `cameraPosition` 世界位姿；`f = (H/2) / tan(fov/2)`，垂直 **FOV 60°**、16:9 |
| 投影 | `u = W/2 + f·x/z`，`v = H/2 - f·y/z`，`z ≤ 1e-4` 丢弃 |
| 排序 | **深度降序 painter**。场景层全平行（XY 平面，z 从 2.9 到 257），不需要 Z-buffer |
| 合成 | 逐像素 alpha over；透视正确插值（权重除 z） |
| 背景 | 用 `*_skybox*_side` 拉伸铺底（`NKSpotSky` 的天穹在运行时生成，包内无网格） |
| 采样 | `uv` 的 v 轴上下翻转（Unity 原点左下，Pillow 原点左上） |
| 抗锯齿 | 2× 超采样后 LANCZOS 缩回 |

实测耗时：2560×1440 / 2× 超采样 ≈ **30 秒/张**，单场景 46~105 绘件、134~210 三角形。

## 四、层结构长什么样

以 `sbg_finale_xbg006_001_02` 的 z 分层为例（相机在 z≈−2，朝 +Z）：

| z | 层 | 举例 |
|:--:|:--|:--|
| 2.9 ~ 4.9 | 近景掩体（<10 单位） | `sbg_finale_c_barrier04~08` |
| 5.8 ~ 55 | 地形网格 | `sbg_wasteland_ground01_c/_m/_n/_f` |
| 70 ~ 120 | 中景建筑 / 塌陷坑壁 | `sbg_finale_nm_sinkhall01~10`、`nn_ground01` |
| 125 ~ 131 | 远景天际线 / 云带 | `sbg_finale_nf_skylinebuilding01`、`nf_cloudn01~10` |
| 135 ~ 257 | 高空云 | `nf_2cloud01~04`、`nm_cloud112`、`nf_cloudfar01` |

近景掩体是**少数带真网格的部件**（170~514 顶点），地形为 12 顶点 × 8~12 三角形平面，其余全是单四边形。

## 五、已知偏差（如实记录）

1. **远景天际线是雾状不透明块**。`sbg_finale_nf_skylinebuilding01`（z=130）底边与左右边为实色雾，静止帧能看到矩形边缘。
   实机该层走 UV 滚动（`Shader Graphs/NKShaderGraph_Background_Scroll`，`_MainTex.m_Scale` + `Vector1_2ECD0BCE` 滚动量）并压在前景岩壁之后，仍可见但被运动模糊掩盖。
2. **云带顶边成直线**。`cloudn10`(z=100.8) / `cloudn07`(z=107.7) 的贴图自身顶边是直切线，投影后是全宽水平接缝。
3. **天穹未按方位采样**。`*_skybox*_upper` / `_under`（64²）是按上下方位 tint 的，静态渲染只用了 `_side` 拉伸；如需精确，要按屏幕 y 混合 upper/under。
4. **不做 UV 滚动与雾**。`_FogDensity` 全为 0（雾关），`*Speed` 只在 `IsOnScroll=1` 时生效，本批均为 0。

## 六、复现

```bash
# 单场景直出
python tmp_sbg_render.py <bundle> out.png 2560 1440 60 <机位序号> <组序号>

# 批量：天穹 + 全部贴图 + 全景，写 00_资源库 并登记
python tmp_import_sbg_20261029.py --apply --render
```
