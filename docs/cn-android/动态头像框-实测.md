# 动态头像框：从国服安卓客户端取 256² 原生帧

> 实测环境：国服安卓 `com.tencent.nikke` 22.1.1（code 2201001），adb 37.0.0 / 1.0.41，已 root。
> 数字均为本机实测；未验证的项单独标注。

## 结论

| 项 | 结论 |
| :--- | :--- |
| 哪个服有 | **只有国服**。国际服 `core` / `dp` 两个桶按 `dynamic` 检索，`icons-dynamic` **0 命中** |
| 原生分辨率 | **256×256**（`icons-dynamic(hd)`）。PC 端只有 `icons-dynamic(sd)` 128×128 |
| 实测体量 | **21 组 / 668 帧**，每组 31–32 帧，1600 ms 循环 |
| 能不能放大 | **不能**。256² 就是原生档；384² 是插值，细节反而更糊，已废弃 |

## 1. 先判族：国际服没有这个东西

```bash
# 国际服七桶（core/dp）解出的 catalog 里检索
SELECT key FROM files_chunktype WHERE lower(key) LIKE '%dynamic%';
# core → 1 条（spotpresentationbase…dynamicprefabcontroller，无关）
# dp   → 0 条
```

`icons-dynamic`、`dynamic_soloraid` 在两个桶均为 0，所以**国际服 PC / 安卓都取不到**，不是端的问题，是族不存在。
国服走 Addressables 明文清单，直接能看到键，见下。

## 2. 资源定位（国服安卓）

| 项 | 值 |
| :--- | :--- |
| 资源根 `$D` | `/sdcard/Android/data/com.tencent.nikke/files` |
| 清单目录 | `$D/com.unity.addressables/`（22.1.1 实测 177 组） |
| 命中的组 | `1077256059.json`（版本相关，换版先按下面的键名重查） |
| HD 键 | `icons-dynamic(hd)_assets_all_d6730d60739ae7627952e3684deb7cf1.bundle` |
| SD 键 | `icons-dynamic(sd)_assets_all_8f6b75a91aa865541c4738952f6d7a20.bundle` |
| HD 解密后 SHA-256 | `40A4278225CE2123B80401B78BE1097A3988C61ED436F928F9E93C381C3A69FD`（2026-09 版） |

SD 与 HD 是两批东西：SD 实测 18 组 / 572 帧 / 128×128，HD 是 21 组 / 668 帧 / 256×256。**要 HD 就只认 `(hd)` 后缀的键。**

## 3. 取件与解密

```bash
export MSYS_NO_PATHCONV=1
D=/sdcard/Android/data/com.tencent.nikke/files

# ① 清单：先确认键还在
adb pull "$D/com.unity.addressables/1077256059.json" build/cn/dynamic_catalog.json

# ② 数据体：整包 pull，不需要 dd
adb pull "$D/UnityCache/Shared/<hashA>/<hashB>/__data" build/cn/icons-dynamic_hd.bundle
```

`<hashA>/<hashB>` 来自清单里的 bucket 路径，不要猜。取回后先读前 4 字节：

- `UnityFS` → 直接 `UnityPy.load()`
- `NKAB` → 先过 NAU 解密（国服 22.1.1 实测是 **NKAB v4**）

解密后核对 SHA-256；哈希对不上说明取了别的版本，别继续往下导。

## 4. 导出与命名

```python
import UnityPy

env = UnityPy.load("build/cn/icons-dynamic_hd.bundle")
for obj in env.objects:
    if obj.type.name not in ("Texture2D", "Sprite"):
        continue
    data = obj.read()
    # data.m_Name 形如 dynamic_soloraid_Alteisen_ANMI_tier4_frame_00
    ...
```

命名规则：

- 帧：`dynamic_soloraid_<Boss>_<画师>_tier<N>_frame_<NN>.png`
- 组名：去掉 `_frame_<NN>` 后缀
- **编号起点不一致**：实测有 `00..31`、`01..31`、`00..30`、`06..37` 四种，**一律按文件名排序取帧序，不要补缺号**

## 5. 合成动图

- 统一 **1600 ms 循环**：32 帧 = 50 ms/帧；31 帧按厘秒均分（5/6 ms 混排），总长仍 1600 ms
- 用 Pillow 存 GIF 会合并末尾相同帧（32 → 27~31），总时长不变；**要保留全部帧就出 APNG**
- GIF 只有 256 色 + 1-bit 透明，**不能拿 GIF 做画质比对**

## 6. 三个坑

1. **256² 不是低清。** 早期按“不够大”判过一次出库，后来查证 256² 正是国服安卓 `icons-dynamic(hd)` 的原生档；PC 的 128² 才是低清。旧那批 384² 是插值放大，已废弃。
2. **包名会骗人。** 原件 `icons-dynamic_8917824c838a7af3c83dc31804e647ef` 的真实键是 `icons-user_frame(sd)_assets_all_8917824c….bundle`（静态框），早期按文件名归错类。**归类按 catalog 键，不按文件名。**
3. **帧前缀不统一。** 动态组里有 `icn_soloraid_*`（沿用图标前缀）和 `dynamic_soloraid_*` 两种，前者不是误分类，是命名沿用；判定动画看帧号是否连续、帧间是否有差分，不看前缀。

## 7. 最小验收

导出后先对这四个数，任一不符就重来：

| 项 | 期望 |
| :--- | :--- |
| 组数 | 21 |
| 帧总数 | 668 |
| 单帧尺寸 | 256×256，RGBA |
| 每组帧数 | 31–32 |
| 首帧 vs 末帧 | 必须不同（相同说明取成了静态图） |

再抽 1 组和游戏内名片对比一次，循环点对得上才算过。

## 8. 适用范围

- 只验证了国服安卓 22.1.1；国服 PC 与其它语服**未验证**。
- 换版本后键名里的 hash 会变，按 `icons-dynamic(hd)_assets_all_` 前缀重查，不要复用旧键。
- 这套方法只解决“取到原生帧”，不涉及头像框与头像的叠放比例；装配参数不在本文范围。
