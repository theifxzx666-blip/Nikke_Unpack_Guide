# PC 端实测结论

PC 国际服客户端实测，版本日期 2026-10-29。与安卓链路同一套容器格式，但**族与文件布局有 10 处差异**，逐条列出。

结论先行：**43 类清单在 PC 端有产物的 37 类**（族名命中 38 类，其中「角色立绘_低清」族在但块物理缺失），其余 6 类：2 类不可得（静态表）、1 类族不存在（动态头像框）、1 类物理缺失（低清）、2 类不适用（派生产物）。

---

## 1. 七项待验证的答案

[README.md](README.md) 里列的七项待办，逐项给了答案：

| # | 待验证 | 结论 |
| :-: | :--- | :--- |
| 1 | 资源根目录位置 | **不在安装目录**，由启动器决定。`Player.log` 有 `trace GetGameResourcePath: kErrorSuccess - <绝对路径>` 一行，直接给答案。本机实测根在 `D:\PanDownload\...\Unity\com_proximabeta_NIKKE`，安装目录 `F:\...\NIKKE\game` 只有 exe 与 `nikke_Data` |
| 2 | 是否使用 chunk 机制 | **是**，`<桶>/chunk/store.cdb` + `store.cdb.idx` 与安卓完全同构 |
| 3 | 清单格式是否同源 | **同源**，头 4 字节 `NKDB`，version 1，AES 密钥明文在偏移 8，segment_size 65,536 |
| 4 | CIDX 是否存在 | **存在**，`CIDX` + u32 版本 + u32 条目数 + N×28 B，尾部 16 B |
| 5 | 键命名是否一致 | **一致**，43 类里点名的族名逐字相同（例外见 §3） |
| 6 | 加壳情况 | **无额外壳**，无完整性校验、无运行时解密，读取即明文 zstd |
| 7 | 版本号对应 | **PC 取不到 `versionName` / `versionCode`**，`dumpsys package` 是安卓独有。改用文件指纹（七桶 catalog 大小 + mtime + 键数） |

> 「PC 端资源目录不在 AppData/LocalLow」这条原始观察**部分成立**：`LocalLow` 下确实只有 `Player.log` 与 `bg-downloader` 日志，资源本体在启动器指定的目录。

## 3. 与安卓的 10 处差异

| # | 项 | 安卓 | PC 实测 |

| 2 | `.nab` 语音 | 未验，没解出过音频 | **`ja` 桶 `.nab` bundle 内就是 `AudioClip`**，UnityPy `AudioClip.samples` 直接出 wav（48,000 Hz / 16 bit / 单声道）。见 §5 |

## 4. `spotmonster` 没有整具模型

单包对象极多（`xbg001`：GameObject 1,673 / Transform 1,673 / ParticleSystem 778 / Mesh 217 / Texture2D 175），
看起来像完整模型，但采样 12 个型号后：

| 型号 | Mesh 数 | 最大顶点 | 最大三角面 | ratio | 最大网格名 |
| :--- | --: | --: | --: | --: | :--- |
| bba001 | 18 | 468 | 768 | 1.641 | fx_bba001_appearance_fbx_02 |
| btg001 | 10 | 984 | 980 | 0.996 | cm0010_legs_skin |
| eba001 | 16 | 857 | 488 | 0.569 | eba001_shield_01_left |
| xbg001 | 217 | 1,840 | 920 | 0.500 | fx_eba003_sk4_shield_fbx_02 |
| bca001 / bcg001 / bea001 / beg001 / bma001 / bmg001 / bta001 | 各 1 | **3** | 1 | 0.333 | `cm_bone_00_skin` 一类 |

`cm_bone_*_skin` / `common_ground_bone_*` 只有 3 顶点 1 三角面，是**骨骼占位**；`fx_*` / `fbx_*_particle` 是特效件。
⇒ 该族装的是骨骼占位、特效与贴图，**不含整具高模**。

这直接改写了两条判据：

- 「`spotmonster(hd)` 出 .glb 保骨骼和动画」在 PC 端不成立。
- 「`triangles / vertices ≥ 1.5`」不能用来选主体。它是给完整模型定的，特效面片天然 < 1（实测 0.33~0.99）。**必须先按顶点数量级筛，再用 ratio 做合法性检查。**

## 5. `.nab` 可以直接出音频

`ja` 桶 `files_chunktype` 里 `.nab` 共 2,190 个（`en` / `ko` 各 2,190，`saus` 1，合计 6,571）。
取任一：

```python
blob = fetch('ja', key)            # 常规 chunk 链路，不是 raw 层
open('x.bundle','wb').write(blob)
env = UnityPy.load('x.bundle')
for o in env.objects:
    if o.type.name == 'AudioClip':
        for name, wav in o.read().samples.items():
            open(name + '.wav','wb').write(wav)
```

实测产出：`48000 Hz / 1 ch / 16 bit / 7.23 s`。
`.nab` 是 bundle 的外层后缀，**内部是标准 `AudioClip`**，不存在另一层自研封装。

## 6. 低清缺失的定论（同时适用于安卓）

原「已知缺口 #1 / #2」是一件事的两端。PC 端做了决定性验证：

```
256 + Σ(idx.size)  ==  store.cdb 实际字节数   ?
```

| 桶 | `store.cdb` | `256 + Σ(idx.size)` | 差 | 索引段间隙数 |
| :--- | --: | --: | --: | --: |
| core | 7,172,646,468 | 7,172,646,468 | 0 | 0 |
| dp | 14,461,327,084 | 14,461,327,084 | 0 | 0 |
| fd | 2,268,657,905 | 2,268,657,905 | 0 | 0 |
| ja | 4,433,324,101 | 4,433,324,101 | 0 | 0 |
| saus | 19,706,390 | 19,706,390 | 0 | 0 |

`.idx` 的偏移区间首尾相接、无空洞，且总和恰好等于文件大小 —— **`.idx` 100% 覆盖 `store.cdb` 的物理字节**。

⇒ **`.idx` 里查不到的 chunk，物理上就不在文件里**。`pak_offset` 反推不出没写进去的字节，这条路是死的。

缺失块只能靠**游戏内触发按需下载**补齐。

PC 端缺失规模（同样是纯低清）：

| 桶 | 缺失块 | 压缩后 | 归属 |
| :--- | --: | --: | :--- |
| dp | 49,507 | 2.41 GB | `scenariobackground(sd)` 20,189 / `spinecombatcharactergroup(sd)` 10,365 / `spinestandingcharactergroup(sd)` 7,888 / `icons-char-full(sd)` 1,481 / … |
| core | 24,516 | 0.76 GB | `spotbackground(sd)` 15,182 / `spotmonster(sd)` 9,327 / `icon-spriteatlas(sd)` 5 / `uipatch(sd)` 2 |

这与安卓侧「缺 13,900 全是 `(sd)`」完全同构，怀疑同一机制。**建议在安卓侧跑同一条 Σ 校验**，若闭合则 #1 #2 可一并关闭。

## 7. 静态表：PC 端路径不存在

安卓在 `cache/StaticData.pack`。PC 端**没有对应文件**。

最容易被误判的是 `core/raw` 与 `dp/raw` 下那两个 `.db`（8,860,868 B / 7,497,241 B，同样是 NKDB 加密）。
解开后确实是 SQLite，但表结构是：

```
entries / entry_data / keys / key_entries / internal_ids / types / provider_ids / resource_prov
```

这是 **Unity Addressables 的目录数据库**，不是 MemoryPack 静态表。
判据：静态表是 ~179 张业务表（`CampaignStageTable` / `UserTitleTable` / `ItemConsumeTable` …），而这里是 8 张地址索引表。

⇒ PC 端拿不到 `CampaignStageTable.FieldMonsterId` 这类数值，第 35、40 两类不可得。

## 9. PC 端取件与安卓的唯一算法差异

安卓要 `dd` + `pull`（设备侧切块），PC 端文件就在本地，直接按 `.idx` 偏移读：

```python
idx = load_cidx('store.cdb.idx')          # hash -> (pos, size)
cdb = open('store.cdb', 'rb')
for foff, h, orig in chunks_of(fid):       # ORDER BY file_offset
    pos, size = idx[h]                     # 缺失即抛，不要跳过继续拼
    cdb.seek(pos)
    blob = cdb.read(size)
    data = dctx.decompress(blob, max_output_size=orig + 1024)
    assert len(data) == orig and foff == written
    out += data
```

三道约束与安卓相同（顺序、长度、不许静默跳过），只是省了 4096 对齐与断批优化。

**PC 端下载期也有分段**：`chunk/ranges/<pak>_<start>_<end>.tmp`（545 段 × ~128 MiB），
下载完成后合并为 `store.cdb` 并清空 `ranges/`。**在 `ranges/` 非空时读 `store.cdb` 会拿到残缺文件**，
判就绪必须两者齐看 —— 与安卓「阶段 0 检查下载已收尾」是同一件事。

## 10. 一个必须记住的 UnityPy 坑

`Mesh` 在 UnityPy 1.25.4 里**没有 `m_VertexCount` 属性**，`obj.read()` 只返回带 `export` / `save` / `object_reader` 的壳。
写 `obj.read().m_VertexCount` 抛 `AttributeError`，若被 `except: pass` 吞掉，会得到「这个包没有 Mesh」的假结论 —— 实测因此误判了 40 个候选包。

正确写法：

```python
t   = obj.read_typetree()                                   # -> dict
v   = t['m_VertexData']['m_VertexCount']
tri = sum(s['indexCount'] for s in t['m_SubMeshes']) // 3
cmp = t['m_CompressedMesh']['m_Vertices']['m_NumItems']     # 0 表示未压缩，顶点数可信
```

同类型错误还有 `zstd.decompressobj().decompress(max_output_size=)` —— 那个参数名只在
`ZstdDecompressor.decompress()` 上存在，`decompressobj` 那边叫 `max_length`。
**参数/属性名写错 + 吞异常 = 整轮假阴性**，两次都栽在这里。

## 12. 装配型场景（`spotbackground`）已可出全景

第 18 类「场景背景」在 PC 端有两种形态，此前只解了第一种：

| 形态 | 族 | 交付 |
| :--- | :--- | :--- |
| 单张全景 | `scenariobackground(hd)` | 直接导 `Texture2D` |
| **装配型** | `spotbackground(hd)_assets_sbg_*` | 需还原装配后渲染 |

2026-10-29 把 5 个 `sbg_*` 包（四周年 finale / skyfall）全部渲出 2560×1440 全景。要点（细节见 [02-场景装配与离线渲染.md](02-场景装配与离线渲染.md)）：

- **贴图不在 Material 上**：`_MainTex` 的 `m_FileID=2` 指向包外；真正绑定是 `RuntimeTextureInstanceSetter{_sprite,_material}`，数量等于 `Texture2D` 数。
- **41/46 个 `MeshFilter.m_Mesh` 为 0**：Sprite 四边形运行时按 `m_Rect / m_PixelsToUnits` 生成。「无 Mesh」不等于无资产。
- **`m_IndexBuffer` 为空时用隐式顺序索引**（起点 `firstVertex`）；照 `firstByte` 解析必 `struct.error: buffer size 0`，5 个包栽了 4 个。
- **一个 bundle 可含多个场景**：`_01_custom` = 两个 `SpotSingleMap`（105 + 46 绘件 / 10 机位），须按 8 个 root 分组，否则叠图。
- **机位在 `NKSpotCoverManager.cameraPosition`**（GameObject，需转 Transform）；Unity 相机前向 = 旋转矩阵 **+Z 列**。
- 环境无 GL 库（只有 numpy + Pillow）⇒ 自写软光栅：垂直 FOV 60°、2× 超采样、深度降序 painter（图层全平行，无需 Z-buffer），2560×1440 约 30 s/张。

**已知偏差**：远景天际线（`sbg_finale_nf_skylinebuilding01`）是不透明雾块，静止帧见矩形边；云带顶边为直切线，投影后成全宽接缝。两者都是贴图自身边界，实机靠 UV 滚动与前景遮挡掩盖。
