### 两条易错点

**① 小头像 (5) 只存在于一个 `_assets_all` 大图集**

没有 `icons-char-si(hd)_assets_c<ID>...` 这种键。全角色小头像打在一个大图集里（实测 558 个 Sprite），
必须整包取完再按 sprite 名挑。曾因正则写窄误判「没有 si 族」，整批漏采。

**② 小头像无法从半身像裁切还原**

多尺度模板匹配实测 MAE 28~67，明显失配。它是独立绘制的资源，只能从 si 图集取。

### 立绘的两种规格不能混

| 产物 | 来源 | 用途 |
| :--- | :--- | :--- |
| `c<ID>_<皮肤>.png` | Sprite（紧密裁切） | 展示、拼图，与母库「角色立绘」同规格 |
| `c<ID>_<皮肤>_uc_tex.png` | Texture2D（整幅画布） | 需要原始画布时用，与母库「角色立绘HD」同规格 |

判据：母库里 `icons-char-full(hd)_assets_c082_00` 的 Sprite = **405×761**，与既有的
`角色立绘\丽塔_c082_00\c082_00.png` 完全一致 —— 说明母库「角色立绘」就是本族 Sprite，可直接并库。

### 活动剧情必须查两张表

**只查 `Locale_MainScenario` 会漏掉多章式活动。**

真实翻车：某期联动活动被判「没有剧情」。实际它是多章式活动，
正文全在 `Locale_SubScenario`，共 3,327 条 —— 两章 + 双轨（方舟侧 / 联动角色侧）。

修正后的口径：

| 表 | 装什么 |
| :--- | :--- |
| `Locale_MainScenario` | 主线 + **单章式**活动 |
| `Locale_SubScenario` | **多章式**活动（125+ 部）+ 支线 / 内容关 |
| `Locale_SideStory` | 番外篇 |

**判据：`不可归组数必须为 0`。** 非 0 说明有内容被丢在分组外面。

### 活动数统计有三道坎

| 坎 | 现象 | 后果 |
| :--- | :--- | :--- |
| PascalCase 代号 | 早期活动代号是 `BunnyX777` 这类 | 只匹配小写会**整部丢掉**（实测少 1,289 条） |
| 大小写重复 | `BlueWaterIsland` 与 `bluewaterisland` 是同一活动 | Windows 目录不分大小写 → 后写覆盖先写 |
| 双表重复 | 同一活动两表都有条目 | 直接相加会多算 |

后两条**不会进「不可归组」**，只能靠「分组数 vs 目录数」对不上才发现。脚本要两样都打印。

### BOSS 模型的四个坑

**① 阶段归属不能靠名字猜**

包里 1 阶段 / 2 阶段是两套并列的**变体根**（`x_1phase_var` / `x_2phase_var`）。
按「最近一个名字带 1phase/2phase 的节点」判定归属会错 ——
名叫 `*_1phase_*` 的网格可能实际挂在 `2phase_var` 下。

**正确做法：按 `_var` 变体根判定。**

**② 子网格材质必须按下标对应**

Unity 的 `Mesh.m_SubMeshes` 与 `Renderer.m_Materials` 按下标一一对应。
只取 `m_Materials[0]` 会导致 60~78% 的顶点用错图集 —— 画面看起来「碎、丢细节」，
但几何完全正确。**碎的不是几何，是贴图。**

**③ 动画绑哪套骨架 ≠ 包名写的阶段**

某条以 `2phase` 命名的动画，338 个骨骼路径全部命中 1 阶段骨架。
按 2phase 取 → 0 条通道 → 导出一个不动的静态模型，**且不报错**。

**④ 「模型飞出画面」通常是动画内容，不是数据坏了**

登场 / 战败动画本来就会把整具模型搬走（下落、部件炸飞到 z≈-148）。
判断方法：看四元数模长是否全部 = 1.000（是则没偏）、看单轴是否绕圈（是则是有意轨迹）。
**掐掉等于把演出删了。正确做法是改取景，不动数据。**

### BGM 的两个实测坑

**① 音频是无扩展名的裸 WAV**

客户端里这些是 RIFF/WAVE（44.1 kHz / 16 bit / 立体声）但没有扩展名，双击打不开。
交付时出 `.wav`（原样改名，内容零改动）+ `.mp3`（256 kbps，体积约 1/6）。

**② 有的曲目包内没有独立 AudioClip**

只有 `SoundCueData`，音频实际在 `_intro`（几秒）与 `_loop`（一百多秒）两条里。
两段相加与该曲目在游戏内唱片机表里的时长对得上，才敢合并标注。

## 八、需求 → 方案 路由表

用户的原话通常很短，必须翻译成可执行档位。**判据看「时间锚」和「范围词」**。

| 用户原话特征 | 判档 | 产出 |
| :--- | :--- | :--- |
| 「这期出了什么」「版本更新内容」「做个报告」 | A 全量期次 | 两段式目录 + 两份 PDF |
| 「新增了哪些」「只要新的」「更新后多了什么」 | B 版更增量 | 九段式 + 入库登记 + 联系表 |
| 「先把图给我」「今天就要」 | C 当日快拆 | 平铺分类 + 结果 md |
| 「某某角色的立绘」「某个活动的插画」 | 定向 · 单类 | 单目录 |
| 「模型能不能动」「3D 的」 | 定向 · 模型 | `.glb` + 查看器 |
| 「剧情文本」「台词」 | 定向 · 文本 | `.tsv` / `.md` / 阅读版 html |
| 「拆包怎么做的」「密钥从哪来」 | 文档 | 不拆包，只写说明 |

### 需求不全时的默认值

按下表补，并把补的部分写进交付说明（让人知道哪些是默认带的）：

| 缺什么 | 默认取 |
| :--- | :--- |
| 未说范围 | B 增量（最常用） |
| 未说规格 | 只取高清版，不取低清版 |
| 未说图种 | 立绘 + 半身像 + 小头像（三件套） |
| 未说是否入库 | 不入库，只交付 |
| 未说是否出 PDF | 不出 |
| 未说语言 | 默认语言；涉剧情时出多语 tsv |

### 反向确认清单

需求明确后，动手前先回这几句（避免返工）：

1. **只要新增，还是这一版全部？**
2. **高清版就够，还是低清也要？**
3. **要不要入库？**（入库要走查重 + 改名 + 登记，工作量大一倍）
4. **要不要出联系表 / PDF？**
5. **有没有时间点要求？**（影响判 A/B/C 档）
